After launch

Improvements we deliberately queued so launch could happen sooner — none of them block going live. Each card says what it is, why it's worth doing, and roughly when.

First weeks after launch Later / when it hurts

1 · Watch real users with Sentry dashboards

First weeks

Sentry is wired up (see Launch tasks #7). The follow-up is simply looking at it: once real users arrive, check the Sentry dashboard twice a week. Any red spike is a bug your users found before you did.

  1. Log into sentry.io → your project → Issues.
  2. Sort by frequency; anything new after a release is worth a fix.
  3. Hand the top error to the coding agent — it already has the stack trace and can fix it.

Effort: 15 minutes twice a week. Do it from day one.

2 · Race-condition check on real refunds

First weeks

The refund logic is protected by an atomic claim (two people can never both trigger the same refund), proven by tests. This task is its real-world confirmation: while a payment is "processing", open the app on two devices and try to cancel the same booking at the same moment. Exactly one cancel should win; the other should see a clean message.

  1. Create one paid booking with a card (live mode after launch).
  2. Open the session's Cancel screen on two devices at once; tap Cancel on both.
  3. Check the Stripe dashboard: exactly one refund appears.

Effort: 15 minutes once. Do it during the first week of real payments.

3 · Video calls inside the app

First weeks

Today, joining a session opens the Daily room in the phone's browser — fully working, but it leaves the app. Embedding the room natively keeps users inside 1on1 and feels far more polished.

  1. The coding agent adds the @daily-co/react-native-daily-js library and replaces the browser hand-off with an in-app room screen.
  2. Re-run the paid-booking join test on the emulator — mic, camera, and the call itself should work without leaving the app.

Effort: ~1 day of agent work. Worth doing before inviting many hosts.

4 · Instant message updates

When chat traffic grows

Messages currently refresh every 15 seconds — fine for low volume. Supabase Realtime delivers them the instant they're sent instead.

  1. The coding agent enables Realtime on the messages table and swaps the 15-second poll for a live subscription (the polling stays as a safety net).
  2. Test: two devices chatting — new messages should appear with no reload.

Effort: ~half a day. Prioritize once hosts and clients chat daily.

5 · Host self-service payouts (Stripe Connect)

Before scaling hosts

Right now hosts are paid manually off-platform after each session — fine for a handful, unmanageable at scale. Stripe Connect automates it: after a session completes, the host's cut moves to their bank account automatically and tax forms are handled.

  1. Activate Connect in the Stripe dashboard; choose the "Express" type.
  2. The coding agent adds an onboarding screen where each host connects their bank account (Stripe hosts the forms and identity checks).
  3. A scheduled job (Supabase cron) pays each completed session after its cancellation window passes.
  4. Test with one friendly host and one small real payout before switching everyone.

Effort: ~2–3 days of agent work plus one Stripe review. Do before onboarding more than ~10 hosts.

6 · Speed & polish pass

After first feedback

A grab-bag of quality work queued from code review: smoother navigation transitions, virtualized long lists (the catalog stays fast at 500+ hosts), and visual polish on screens users flagged. None of it is urgent; all of it compounds.

  1. Collect 2–3 weeks of real-user feedback (app-store reviews + Sentry + support email).
  2. Rank the top five annoyances and hand the list to the coding agent as one batch.

Effort: 1–2 days per batch. Repeat monthly.

7 · Push notifications

Deliberately deferred

Booking confirmations and reminders currently live inside the app. Push notifications ("Your session starts in 1 hour") reduce no-shows but require Apple/Google developer setup and careful opt-in timing, so they were deferred by decision.

  1. The coding agent wires Expo push notifications and asks permission only after a user's first successful booking (opt-in at a meaningful moment).
  2. Start with two notifications: session reminder (24h + 1h) and message-received.

Effort: ~1 day. Do when no-shows or slow replies start hurting.

This list is reviewed monthly — anything users actually complain about jumps the queue. See also the pre-launch tasks.
